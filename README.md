# Sunny Shorts

A daily YouTube Shorts pipeline for **Sunny y Luna**, a Spanish-language cartoon double act for a general audience: Sunny (an over-excited star) and Luna (the tired, deadpan moon who shares the room).

Everything the audience sees or hears is in Spanish (neutral Latin American). Language settings: `CONTENT_LANGUAGE` (default `es`), `VOICE_LANGUAGE` (`es-US`), `SCRIPT_LANGUAGE`, and `MOON_NAME` (`Luna`). In code the second character's id stays `moon`.

Each run takes about 3–5 minutes:

```
Gemini writes the script ─► Gemini TTS voices each line ─► Rhubarb makes mouth shapes
        ─► Remotion renders a 1080×1920 MP4 ─► YouTube API uploads it
```

Both characters are drawn in code (`src/remotion/sunny/Sunny.tsx`, `src/remotion/moon/Moon.tsx`), so they look exactly the same in every
episode. Only pose, expression and mouth change. Each line has a `speaker`; Gemini voices both characters in one multi-speaker request
(`GEMINI_VOICE` for Sunny, `GEMINI_MOON_VOICE` for Luna, default `Gacrux`).

## Project layout

| Path | What it does |
| --- | --- |
| `character/bible.md` | Sunny's personality, audience rules and theme list. Sent to the script writer every run. Edit this to steer the show. |
| `src/remotion/` | The video: Sunny rig, scenes (park, bedroom, rainbow), captions, end card. |
| `src/pipeline/run.ts` | The daily run: script → voice → lip sync → render → upload. |
| `src/pipeline/script.ts` | Script writer: Gemini (default) or Claude. Returns a validated episode script. |
| `src/pipeline/tts.ts` | Voice: Gemini TTS (default) or ElevenLabs, plus an offline `espeak` voice for testing. |
| `src/pipeline/lipsync.ts` | Runs Rhubarb Lip Sync on each line. |
| `src/pipeline/upload.ts` | YouTube upload with the audience setting, scheduled publish. |
| `src/pipeline/facebook.ts` | Facebook Page Reels, scheduled to the same time as YouTube. |
| `src/pipeline/tiktok.ts` | TikTok Direct Post (optional; skipped without TikTok secrets). |
| `data/history.json` | Past episodes, so the writer doesn't repeat themes. Committed back by the workflow. |
| `data/sample-episode.json` | A hand-written episode for testing without API keys. |
| `assets/music/` | Background music; one file is picked at random and mixed quietly. `sunny-bounce.wav` is generated by code, so it is free to use. Add only tracks you have a licence for. |
| `assets/sfx/` | Sound effects (pop, whoosh, boom, boing), generated by `npx tsx src/scripts/make-audio-assets.ts`. |
| `.github/workflows/daily-episode.yml` | Runs every day at 1:13 PM Pakistan time; the Short goes public at 3:00 PM. |

## Run it locally

Needs Node 22, `ffmpeg`, and [Rhubarb Lip Sync 1.13](https://github.com/DanielSWolf/rhubarb-lip-sync/releases) on your PATH
(or set `RHUBARB_PATH`). For the offline test voice, also install `espeak-ng`.

```bash
npm install
cp .env.example .env

npm run episode:sample      # sample script + robot voice, no keys needed, no upload
npm run studio              # open Remotion Studio to tweak the animation
npm run episode -- --no-upload   # real run with Gemini script + voice, skip YouTube
npm run episode             # full run
```

Output goes to `out/<date>-<title>/episode.mp4`, next to `script.json` and `props.json`.

## One-time setup

### 1–2. Gemini (script and voice)
Get an API key at aistudio.google.com and set `GEMINI_API_KEY`. The same key writes the script
(`gemini-3.8-flash`) and voices it. To use Claude for scripts instead, set `SCRIPT_PROVIDER=claude`
and `ANTHROPIC_API_KEY` (from platform.claude.com). Try a few upbeat voices
(`GEMINI_VOICE`: Puck, Leda, Sadachbia, Laomedeia, Fenrir) with `npm run episode -- --sample --no-upload`,
pick one, and keep it forever; the voice is part of Sunny's identity. `GEMINI_STYLE` sets the delivery
for every line, and `VOICE_PITCH=1.1` raises the pitch a little if the voice sounds too grown-up.

Gemini returns no word timings, so captions are timed by word length. The mouth is still exact,
because Rhubarb reads the audio itself. If you want frame-exact captions, switch to ElevenLabs:
`TTS_PROVIDER=elevenlabs` plus `ELEVENLABS_API_KEY` and `ELEVENLABS_VOICE_ID`.

### 3. YouTube
1. In Google Cloud Console, create a project and enable **YouTube Data API v3**.
2. OAuth consent screen: External, add yourself as a test user, add scope `youtube.upload`.
   Then **publish the app** (Testing mode refresh tokens expire after 7 days).
3. Credentials → Create OAuth client ID → **Desktop app**. Put the ID and secret in `.env`.
4. Run `npm run auth:youtube` on your computer, approve with the channel's Google account,
   and copy the printed `YOUTUBE_REFRESH_TOKEN` into `.env`.
5. Submit the **YouTube API Services audit form** for the project. Until the audit passes, every
   video uploaded through the API is locked to private, whatever `UPLOAD_MODE` says.

Quota: the default YouTube API quota easily covers one upload a day.

### 4. GitHub Actions
In the GitHub repo, add under Settings → Secrets and variables → Actions:

- Secrets: `GEMINI_API_KEY`,
  `YOUTUBE_CLIENT_ID`, `YOUTUBE_CLIENT_SECRET`, `YOUTUBE_REFRESH_TOKEN`
- Variables (optional): `GEMINI_VOICE`, `VOICE_PITCH`, `UPLOAD_MODE`, `PUBLISH_TIME`, `PUBLISH_DELAY_DAYS`, `SCRIPT_PROVIDER`

Run it once by hand from the Actions tab (**Daily Sunny episode → Run workflow**, mode `test`
first, then `no-upload`). The MP4 is attached to each run as a download for 14 days.

### 5. Facebook Reels
Each episode is also posted as a Reel on your Facebook Page and scheduled for the same 3 PM slot
(`publish-now` posts it straight away). Reels can only go to a **Page**, not a personal profile.

1. At developers.facebook.com, create an app (use case: *Manage everything on your Page*).
   Add yourself as admin. Fill in a privacy policy URL, then switch the app to **Live**.
   In Development mode, Reels are visible only to people with a role on the app.
2. Put `FACEBOOK_APP_ID` and `FACEBOOK_APP_SECRET` in `.env`.
3. In Graph API Explorer, select the app, click *Get User Access Token*, tick
   `pages_show_list`, `pages_read_engagement` and `pages_manage_posts`, and approve for Sunny's Page.
4. Run `npm run auth:facebook` and paste that token. It prints `FACEBOOK_PAGE_ID` and a Page token
   that never expires (it stops working only if you change your Facebook password or remove the app).
5. Add repository secrets `FACEBOOK_PAGE_ID` and `FACEBOOK_PAGE_TOKEN`.
6. Run the workflow in `facebook-test` mode. It saves the sample as a **draft** Reel on the Page
   (Meta Business Suite → Content → Drafts), so you can check it without posting anything.

Reels are labelled as AI-generated (`is_ai_generated`). Set the repository variable
`FACEBOOK_ENABLED=false` to pause Facebook without removing the secrets.

### 6. TikTok (optional, currently on hold)
TikTok is switched off. To turn it on, finish the steps below and set the repository variable
`TIKTOK_ENABLED=true`.

The same video is posted to TikTok right after the YouTube upload. TikTok has no scheduling in
its API, so it goes live as soon as it is posted (around 1:20 PM), not at 3 PM.

1. At developers.tiktok.com, create an app. Add the products **Login Kit** and
   **Content Posting API** (turn on **Direct Post**). Request the scopes `user.info.basic` and
   `video.publish`.
2. Register a redirect URI: any https page on a site you own (verify the domain in the app's
   URL properties). Add a privacy policy and terms URL; TikTok asks for both.
3. Put `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET` and `TIKTOK_REDIRECT_URI` in `.env`, run
   `npm run auth:tiktok` on your computer, approve with Sunny's TikTok account, and paste the
   address you land on. It prints `TIKTOK_REFRESH_TOKEN`.
4. Add repository secrets `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`, `TIKTOK_REFRESH_TOKEN`.
5. Add `GH_PAT`: a fine-grained personal access token for this repo only, with
   **Secrets: Read and write**. TikTok sometimes replaces the refresh token; the workflow uses
   `GH_PAT` to save the new one so the next day's run still works.

**Until TikTok audits the app**, posts are forced to *Only me* and the TikTok account must be
set to private. The pipeline detects this and posts as *Only me* automatically. Apply for the
audit in the developer portal (TikTok reviews how the app follows its Content Sharing
Guidelines). After approval, posts follow `TIKTOK_PRIVACY` (default `PUBLIC_TO_EVERYONE`).
Videos are labelled as AI-generated content (`is_aigc`).

If TikTok fails, the YouTube upload still counts and the run is marked failed so you get an
email. `--no-tiktok` skips TikTok for a run.

## Daily schedule

The workflow starts at **1:13 PM Pakistan time** every day. It makes the episode, uploads it as
**private**, and YouTube makes it public at **3:00 PM** (`PUBLISH_TIME`). If a run finishes after
3 PM (for example a manual run in the evening), the video is scheduled for 3 PM the next day.

Between upload and 3 PM you can watch it in YouTube Studio (Content → Scheduled) and delete or
edit it if something is off. To get a full day to review instead, set the repository variable
`PUBLISH_DELAY_DAYS=1`.

Manual runs (Actions → Daily Sunny episode → Run workflow) have three modes:
- `test`: sample script and robot voice. Needs no keys. Use it to check the setup.
- `no-upload`: real Gemini script and voice, no YouTube. The MP4 is in the run's artifacts.
- `full`: the same as the daily run (public at 3 PM).
- `publish-now`: like `full`, but public as soon as it's uploaded.

## Content rules that matter

- **Audience setting.** Uploads are marked *not made for kids* (`MADE_FOR_KIDS=false`) because
  `character/bible.md` aims the show at teens and adults. The setting must match the content: if
  you ever turn the bible back towards young children (counting, colours, nursery-style lessons,
  talking to the viewer as a child), set the repository variable `MADE_FOR_KIDS=true` at the same
  time. YouTube can override a wrong setting, and under COPPA the channel owner is responsible.
- **Mass-produced content.** YouTube can refuse monetisation for repetitive, template-made
  videos. The theme rotation, the history check and the varied scenes help, but the strongest
  signal is a human looking at each episode. Use the review window, and every so often make a
  special episode by hand with `--script=my-episode.json`.
- **Music.** Only use tracks you have a licence for (YouTube Audio Library is safe).
